# Backend/frontend redesign: review findings (2026-10-01)

`frontend/` (about 8k lines), and how they relate to the legacy
`archive/server/`. Backend suite at that commit: 21 files, all passing.
Legacy suites and the Playwright visual smoke were **not** run.

**Evidence legend.** `[R]` = reproduced by running real project code in a
sandbox (CPU only, no XPU, no real SDXL, no browser). `[C]` = read from the
source, not executed; treat as a strong lead, confirm before relying on it.

**Severity.** High = data loss, a state that blocks the app until restart, or
unauthenticated write/exec. Medium = wrong behaviour in a plausible situation.

## 3. What is good (do not "fix")
- Layering holds: an AST audit found no inward/outward import violations; the
  domain imports no third-party code.
- Zero `innerHTML` sinks in the frontend; everything uses `textContent`.
- Path sandboxing for relative asset paths is sound, including symlinks.
- Compare-and-set per state transition is applied consistently.
- `spawn()` wraps every launch failure in `TrainingLaunchError`.
- Config writes are atomic (temp + replace).
- The tests' `try: ...; check(False) / except X: check(True)` idiom is correct
  (the failing branch is inside the `try`), so those tests are not vacuous.
- The real composition root is exercised by five API tests.

## 4. Where quality needs to improve (instructions for a coding AI)

Apply these to every change in `backend/` and `frontend/`. Each rule comes
from a finding above.

1. **Every background thread needs a crash-repair path.** If it can die, the
   row it owns must still reach a terminal state. Copy the graph supervisor's
   pattern; add a test that kills the worker mid-run. (F-01)
2. **Everything from outside the process is hostile input**: files the
   trainer writes, request bodies, settings values, uploaded names. Parse per
   record, coerce types, tolerate partial and non-finite values, never let one
   bad record end a loop. (F-01, F-03, F-07)
3. **Validate first, then act.** No row, directory or file may be created
   before every check has passed; if an action sequence can fail midway, make
   the failure path leave a consistent state. Commit DB changes before
   deleting files. (F-02, F-05, F-15)
4. **Never emit non-JSON.** Sanitize at the serialization boundary and test
   with a strict parser. (F-03)
5. **No silent swallowing.** `catch { return; }`, `except Exception: return
   default` and similar must count or surface what they drop. A swallowed
   error in a monitoring tool hides exactly the failures it exists to show.
   (F-03, settings `get()`)
6. **Frontends resync on every (re)connect** and treat an event stream as
   lossy. (F-09)
7. **Secure by default.** Allowlist Host, check Origin/token on writes, limit
   extensions and sizes, stream and atomically rename uploads, never let one
   endpoint choose what another executes. (F-06)
8. **Test failure paths, not only happy paths.** For every start/write flow
   add a test where a dependency raises; for every parser add torn,
   malformed, truncated, NaN and empty cases; use the reproductions
   (appendix) as the starting point.
9. **Treat "legacy parity" as a warning label, not a justification.** Several
   defects above are faithful ports. Confirm the behaviour is wanted.
10. **Docs must be true.** Do not write a guarantee (such as "logs stay
    untouched") without a test that proves it. Concretely: README,
    `docs/architecture.md` and `docs/setup.md` all failed to mention
    `backend/` or `frontend/` at all when the backend had been the entry
    point for weeks.
11. **One implementation per concern.** The two process gateways, the
    near-copy `config_schema.py`/`config_ui_data.py` (about 92% identical to
    legacy) and the `build_services` twin of `bootstrap.py` will drift. Fix
    in the new copy only, share code, or delete the legacy copy at M9.
12. **Keep units small.** `schemas.py` is 900 lines (split by API module),
    `GraphRuntime.validate` is 171 lines (split per pass), `monitor.js` and
    `loss_chart.js` are about 680 lines each.
13. **Put the frontend under test.** The gate only runs `node --check`; add
    tests (even a small DOM harness) for event handling, reconnect resync and
    non-finite values, and put the Playwright smoke in the gate or document
    why not. Remove the hardcoded home path from `scripts/full_gate.sh`.

## 5. Suggested order of work

## 8. What the remediation was

Grouped by what changed rather than by the order it landed in, since the
order is history and the subject is what a reader needs.

- **The run supervisor and the progress reader** (F-01, F-02, F-07) — the
  byte-offset reader, `_guard`'s `_fail_leftover()`, and the whole
  post-insert start sequence wrapped: `run_created` is published before
  `run_failed`, because the sqlite repo re-hydrates entities and the launch
  object's event buffer is drained first.
- **Serialisation and the frontend event path** (F-03, F-09) —
  `json_safe` / `SanitizingJSONResponse` at the REST, SSE and monitor
  boundaries; `ClientBuffer` instead of the drop-newest queue; and the
  loud diverged marker replacing a silent `catch { return; }`.
- **Dataset integrity and the run-id collision** (F-05, F-10, F-04) — rows
  commit before files are unlinked, `create` refuses a foreign directory,
  and the collision is refused three ways.
- **The write chain and the raw editor** (F-06 remainder, F-08, F-15) — a
  raw-ASGI `HostOriginGuard` (FastAPI's http-middleware wrapper would
  deadlock the SSE liveness check), pure settings validation, and the
  user's own raw TOML.
- **Process and restart semantics** (F-11, F-12) — a live trainer adopted
  across a restart, and one shared PID-reuse guard gating every signal,
  with the stop grace period raised from 3 s to 15 s.
- **Bounded work, atomic migrations, gate leftovers** (F-14, F-16, F-17) —
  backwards log tail, opt-in item paging, a bounded monitor backlog,
  atomic migrations, and the gate's interpreter discovery.

Two items are recorded rather than silently dropped: F-17's missing
frontend test harness and the documented twins. F-13's follow-up —
isolating graph execution from the API process — was the one finding here
with unfinished work behind it; it is now done, in
[`13-process-isolation.md`](../13-process-isolation.md).
