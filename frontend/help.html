Train an SDXL LoRA on your Intel Arc card: the short path, then where things are
Your first LoRA
  1. Put a checkpoint in place. Copy an SDXL checkpoint (.safetensors) into <models folder>/checkpoints. The models folder is the one you chose in Setup; the page Settings shows it and lets you change it.
  2. Make a dataset. Open Datasets, press New dataset, then Import and give the folder with your pictures. Pictures are read where they are, not copied. A caption file beside a picture (name.txt) is imported with it. Look through the pictures and write or fix captions: they decide what the LoRA learns.
  3. Open the graph editor. In Graph Editor press Quick workflow. Pick the checkpoint, the dataset, an output folder and the length (steps), then confirm. The whole training graph appears, ready to run.
  4. Check it. Validate lists anything missing or wrong, by node. A red node means the server could not load that node type; see Troubleshooting below.
  5. Run. ▶ Run starts training. Watch (top of the editor) shows the loss charts, boards and the run history. ■ Stop stops it.
  6. Use the result. The adapter is a .safetensors file in the output folder you chose, saved every N steps (Save every). Copy it to <models folder>/loras to use it in ComfyUI or any other tool that reads LoRAs.

For a first run keep the defaults except the steps: a few hundred steps at resolution 1024 and batch size 1 show whether everything works before you commit to a long run.

Datasets
  • Datasets are kept in the datasets folder next to the project.
  • Captions have three channels. text is the sentence prompt, tags a comma list, desc a longer description. Switch the channel above the pictures to see and edit each.
  • A picture can be marked good or bad, or discarded, without deleting the file.
  • Sets group pictures inside a dataset.
  • Importing the same folder again keeps the captions you already wrote, unless a caption file exists.
The graph editor
  • A graph is nodes (dataset, model, optimizer, trainer, saver...) joined by edges. The quick workflow builds the usual one; edit it to change anything the form does not offer.
  • The Nodes panel lists every node type; drag one onto the canvas. Inspector edits the selected node's parameters.
  • Arrange tidies the layout and Fit shows all of it.
  • Save keeps the graph in the library; Export and Import file move it to and from a file.
  • Two runs at once are allowed when the card's memory can hold both; otherwise the second is refused or queued, with the reason.
Memory on a 12 GB card
  • If a run does not fit, the cheapest changes are a lower resolution, batch size 1, and a smaller LoRA rank.
  • Close other programs that use the card (browsers with video, games, ComfyUI) before a long run.
  • Every memory setting, with what it costs and gains, is in docs/manual/vram.md.
Troubleshooting
  • Most nodes are red. The server is running without PyTorch. Open Settings and check that the Python interpreter is the virtualenv that Setup installed, then restart the server with the launcher script.
  • A run is refused for memory. Another program or run holds the card. Stop it, lower the batch size or resolution, or run later.
  • The card is not found. Update the Intel graphics driver and check that your user may use the GPU (on Linux usually the render group), then check again in Setup's card step.
  • A run failed. Find it in the run history under Watch and read its log; the last lines usually name the failing node and why.
  • Prompts do not tokenize. The vocabulary files are missing; download them in Setup's Prompt files step, or put them in the project's assets folder.
