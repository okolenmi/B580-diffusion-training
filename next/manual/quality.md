# Quality and training behaviour

Part of the trainer manual (`../MANUAL.md` has the short version). Status: `verified` = run on the B580, `untested` = unit-tested in the sandbox only.

| Lever | Switch | Effect | Status |
|---|---|---|---|
| Learning rate | `--lr`, schedule nodes (`ConstantLR`, `CosineLR` with `min_fraction`, the Warmup addon of a schedule node, `steps`/`start`) | Standard. | verified |
| LoRA+ | `--lora-plus R` / Inject Adapter `lora_plus` (default 1) | The up-projection matrices (B) learn R times faster than the down-projection (A); the optimizer gets separate groups (`attn_self.up@4`). B starts at zero, so with one rate it lags behind. Applies on top of the group multipliers. | none | untested on hardware (TESTING 54) |
| Adapter EMA | `--ema 0.05,0.1` / Adapter EMA node (`sigma_rel`) wired to Save Adapter's `ema` | Power-function averages (EDM2) of the adapter weights, one per width (a fraction of the run so far: 0.05 is about the last 5-10% of the steps). Every saved file is also written once per width as `<name>_stepN_ema<width>.safetensors`. Training never uses the averages. Not saved in a checkpoint of the run, so a continued run starts its averages over. | One extra copy of the adapter on the card per width | untested on hardware (TESTING 55) |
| Gradient-aligned start | `--aligned-init N` / Gradient-aligned start addon on the Trainer (`batches`) | Before step 1 the adapter's A factors become the main directions of the loss gradient measured on the first N batches (LoRA-GA / LoRA-One idea): a randomized SVD from two passes over the same batches, B = 0 after, so the network is unchanged. The new rows keep the old rows' average length. The N batches are consumed from the data stream (training, and the region ladder, start N batches in). LoRA only, a fresh adapter, plain optimizer, no graph. The summary is in the model info as `aligned_init`. | N extra forward/backward passes (twice) before the run | untested on hardware (TESTING 56) |
| Continue an adapter | `--init-adapter FILE` (absolute path or a name under the loras folder) / `init_adapter` on Inject Adapter | Starts from the weights of an adapter made earlier (same rank, targets and kind; a mismatch is an error naming the problem) with a fresh optimizer, schedule and step count. Not combined with the aligned start. | |
| Anchor loss | `--anchor W [--anchor-every N] [--anchor-prompts "a|b"]` / Anchor loss addon on the Trainer | Every Nth step the adapter's prediction under a prompt unrelated to the dataset is pulled toward the base model's (squared difference times W, after the main backward). Reported as `loss_anchor`. Plain optimizer, no graph. | |
| LoRA cleaner | `--clean KEEP [--clean-at N --clean-steps S --clean-mode element/component/magnitude/product/singular --clean-scope global/layer/part --clean-drop PARTS --clean-rescale --clean-lr R --clean-sparsity X --clean-no-freeze]` / LoRA cleaner addon on the Trainer | Gates on every weight (or singular direction) of the adapter train with the loss (and the anchor loss) while the adapter is frozen; the highest KEEP share stays and is frozen, the rest trains from zero. Without training: `magnitude` (the largest weights stay; the best of the first test), `product`, `singular`; `drop` removes parts or regions completely, `rescale` restores each layer's size. Writes `<output>/clean/lora_cleaned.safetensors`, `mask.safetensors` (needed to resume) and `summary.json`. Plain optimizer, no graph. | |
| Batch ramp | `--batch N --batch-first M --batch-first-steps S` / Batch Ramp addon on the Batcher | The first S batches of the run hold M samples (the epoch's planned batches are cut into pieces of M, same shapes, same sample order); later batches have the Batcher's size N. A small batch follows one picture per update (more variety), a large one averages several (steadier, more detail). Memory is planned for N. A continued run skips the batches already trained (`skip`). With `epochs`, the step total counts the actual batches. | the first big batch is a new shape (one compile) | untested on hardware (TESTING 57) |
| Train on top of a LoRA | `Merge Adapter` node between Load Model's denoiser and Inject Adapter (chain several; `strength` scales, negative subtracts) | The saved kohya LoRA is added into the frozen weights when the denoiser loads (`W += strength*alpha/rank * up@down`, rounded once), so the new adapter trains on the merged model. Refuses a file that matches nothing. | A little time at load. The merge is not saved; export the new adapter and merge both when using it. | untested on a real LoRA (equivalence verified on a tiny UNet) |
| Conditioning blend | `--param blend.strength_max=0.5` (and `strength_min`, `probability`, `partners`, `segments`) on the starter's `Blend Conditioning` node | Each sample's text conditioning becomes `caption*(1-s) + partner*s`, s drawn per sample and step from min..max, with chance `probability`; the partner defaults to the empty prompt, or one of the lines of `partners`. Gives the cross-attention a continuum between a caption and nothing instead of one point per caption (or jumps with dropout). Random draws are made after the cached encode, so nothing random is cached. Strength 0 is bit-exact. | Nothing measurable; partners are encoded once up front. Not shown to fix anything by itself. | untested |
| Optimizer choice | `--optimizer AdamWNode|AdafactorNode|CAMENode` | AdamW is the baseline; Adafactor `clip_threshold`, `scale_parameter`; CAME `beta3`. | verified (AdamW) |
| Gradient clip | `optimizer.grad_clip` | Largest total norm; 0 off. Not with `fused`. | untested |
| Adapter kind | `adapter.kind=lora|dora`, `scaling=classic|rank_stabilized`, `alpha`, `dropout` | `rank_stabilized` uses alpha/sqrt(rank) so higher ranks do not shrink. | untested (dora) |
| Region/range control | `adapter.regions`, `adapter.gate*` | Scale or switch off parts of the net; fade the adapter outside a timestep range. | untested |
| Timestep distribution | `noiser.mode=uniform|low|mid|high|logit`, `low`, `high`, `values` | Where noise levels are drawn. | verified (uniform) |
| Parameterization | `noiser.parameterization=eps|v`, `zero_terminal_snr` | Prediction target. | untested |
| Loss weighting | `weighting` node | Per-timestep loss weights. | verified |
| Timesteps per image | `--regions N` (= `noiser.regions=N`, `layout=strata`, `--gradient-policy equal`), `noiser.regions=N`, `noiser.layout=even|strata`, `--gradient-policy mean|equal|project|common` (the Gradient policy addon on the Trainer; none = mean), `--policy-no-normalize`, `--policy-floor`, `--policy-calibrate-every`, the Region Ladder addon on the Noiser (`--regions-from`, `--regions-span`), `--warmup N` | Every image of a batch appears N times in the step, each copy at its own timestep (batch N times larger, planned and split by memory as any batch). `even`: copies equally far apart around the range from a random phase, so one step covers the range; `strata`: copy r draws from the r-th equal part. With `mean` the loss is the average over the copies (steadier loss, no new logic); `equal` scales each region's gradient to unit length and averages (every region counts the same whatever its loss weight). `project` (PCGrad) removes from each region's gradient the part that points against another's; `common` (MGDA) takes the shortest vector in the hull of the regions' gradients, which lowers every region's loss to first order, and with `policy_floor` > 0 skips a step on which the regions cancel. With `equal`, `policy_calibrate_every=N` (3 regions, `strata`, `--time-balance gradnorm`) runs the regions alone only every Nth step, measures their gradient norms, and runs the steps between as one batch with each region's loss weighted by the inverse of its norm (one forward and backward). `project` and `common` run each region's backward alone from zero gradients and need the plain optimizer (not `fused`) and no graph. The Region Ladder node, wired to the Noiser (`--regions 3 --regions-from 9 --regions-span 120`), starts with 9 timesteps per image and falls in equal parts to `regions` over the first 100 batches (more signal in the first updates; not with `policy_calibrate_every`). Its `skip` is the number of batches already trained, so a continued run does not climb again. `--warmup N` ramps the learning rate linearly from 0 over N steps. The logged loss never includes the time balance's weights, so arms with and without them compare. `noiser.perturb=0,0.05,0.1` adds extra noise of that strength to the network input only (target unchanged), by region in turn. With accumulation the policy sees each region's gradient averaged over the window. `equal` with an accumulation of 1 sums the normalised regions on the device as the passes finish (no host copies; the card holds one extra copy of the adapter's gradients whatever the region count) and reports `region_cos_mean` (exact) instead of `region_cos_min`; the other policies and accumulation keep every region's vector in host memory until the passes are done. Step metrics: `loss_region_i`, `region_cos_min` (below 0: two regions pull against each other), `region_shared` (`common`: 1 = identical gradients, 1/N = unrelated), `regions_projected`, `update_skipped`. | untested on hardware (unit-tested; TESTING 43) |
| Self-perceptual loss | Self-perceptual loss addon on the Trainer (`weight`) | The prediction becomes an image estimate (`x0 = x - sigma * eps`); estimate and true image are noised again at an independent uniform timestep with the same noise, and the frozen base network (adapter switched off) compares them by its middle-block features. The relative squared distance, weighted per sample by `1 / (sigma^2 + 1)` so the estimate's error is counted in units of the data and the noisy end does not decide the term, is added to the loss times the weight; the reported loss stays the plain error and the term is reported as `loss_perceptual`. At the training timestep itself the two inputs are identical, so the signal grows with the gap between the two timesteps. eps prediction, an adapter with a gate, no graph; the padded part of a batch is left out. About half a forward and backward more per step. | weight 0.3 (with `equal`, 3 regions, 300 steps) wrecked the pictures: its gradient was about 15 times the plain loss's and, once normalised per region, decided the whole direction; the gradient norms then diverged (1e5 to 1e10). Smaller weights and a bounded image estimate are untried |
| Time balance | `--time-balance off|normalize|speed|dro|gradnorm` (node `balance`) | Reweights the loss per third of the timestep range (weights clipped to 0.25-4x). Each third is compared with its own loss over the first 10 reports: `normalize` weights by 1/that start loss (evens out loss scales), `speed` raises the weight of a third that descends slower than the others, `dro` gives the most weight to the third that has improved least relative to its start. `gradnorm` weights each third by the inverse of its typical gradient norm (measured on steps whose samples all come from that third: batch 1, no accumulation, plain optimizer) so every third moves the adapter equally far; the cheap relative of `--regions` with `equal`. Step line prints the weights; `normalize` can pin the smallest-loss third at the clip, it is a strong setting. | normalize/dro/speed verified (weights move toward equality, speed stays near 1.0 with the `leak`) |
| Balanced sampling | `--balance-sampling P` | Draws timesteps more often from thirds whose loss is high relative to their own start (chance ~ (loss/start)^P; 1 is a start). | verified: with dro the draws sit near 0.33 each |
| Probe | `trainer.probe_every=N`, `probe_items`, `probe_points` | Every N steps compares adapter vs frozen model on fixed samples per third: `probe_rel_t_*` above 1 = the adapter makes that range worse. Diagnostic only; costs a few extra forwards. | untested |
| Padding fill | `--pad-fill zero|mirror` / `buckets.fill` (default zero) | What the padded part of the network input holds. `zero`: a blank strip, noised like the rest. `mirror`: a reflection of the sample's own *noisy* input (same noise values, so no second view of the picture and no extra information); normalisation and attention then see image-like content and the seam is continuous. The loss ignores padding in both. Which trains better is not known: compare two LoRAs. The time probe still uses zero padding. | untested |
| Padding and masks | `buckets.multiple` | Pad latents up to a multiple, loss masked on pad; no pixels cut. | verified |
| Shapes | `latents.mode=fit|center_crop|pad|stretch`, `max_aspect`, `step` | How images become latents; `fit` keeps aspect, cutting at most `step-1` px. | verified |
| Captions | nodes `Captions` (`channel` text/tags/desc), `TagShuffle` (`keep_first`, `drop`), `TagSwap` (`random`/`walk`), `CaptionPool` (`n_min`, `n_max`, `dividers`), `CaptionDropout` (`p`, `substitute`/`empty`) | Prompt variety per epoch; all seeded by `captions.seed`, so epochs repeat identically per seed. The starter trains on the stored captions; `--tag-swap` adds Tag Swap, which cuts every caption to one random tag per epoch (an experiment: a prose caption is cut at its commas). `python -m next.accept prompts` shows what every image trains with. | verified (basic) |
| Seeds | `--set seed.base=N`, or `batcher.seed`, `captions.seed` | Data order, padding offsets, timesteps, noise. A node seed left empty derives from the base and the node id. | verified: same base gives the same losses to ~1e-4 (the device's kernels are not bit-deterministic) |
| Exact repeat | `--set runtime.deterministic=true` | Two runs of the same graph, data and settings give the same numbers: deterministic kernels (some are slower), the global generator seeded from `seed.base` (0 when unset) which also fixes the adapter's starting factors, and no splitting of a batch by predicted memory, so a batch that does not fit runs out of memory instead (lower the batch size). Warnings name any operation that has no deterministic kernel. | new: device test 22 |
| Run length | `--steps N` and/or `--epochs N` (`trainer.steps`, `trainer.epochs`) | An epoch is one pass over the batcher's batches (with accumulation, one step is `accumulation` batches). With both set the run ends at whichever limit comes first; 0 turns a limit off (`--epochs` alone sets steps to 0). A cosine schedule without `total_steps` follows the run's length. | verified (CPU) |
| Save per epoch | `--save-every-epoch N` (addon Every Epoch on the graph) | Saves at the last step of every Nth epoch, in addition to `--save-every` (addon Every N Steps on the graph); the saver hears both without a wire. Step lines show `epoch N` (`end` on its last step). | verified (CPU) |
| Resume | `trainer.start_step`, `batcher.start_epoch`, `LoadAdapter` | Schedule, data order and prompts continue from there. | untested |
| Trend weighting | `--trend-boost B [--trend-mode trend|current] [--trend-penalty P]` / Trend weighting addon on the Trainer | Needs `--regions` 2 or more (the `equal` policy). The timestep range is cut into 12 bins; a sample feeds its two nearest bins in proportion to closeness; every bin keeps a slow (300 steps) and a fast (60 steps) average of the loss. `trend`: a region's bins did better lately (fast below slow); `current`: its own loss is below the slow average. A success is divided by the typical size of successes so far, and the region's weight is `1 + B * z` (z at most 3); with a penalty a region doing worse gets `1 - P * z` (at least 0.25). Applied after each region's gradient is scaled to unit length: it tilts the update and its length follows the average weight. One loss is mostly the draw of image and noise (a region's loss varies by about 50% from step to step), so weights from short histories are noisy; the state is not kept in a resumed run. Step lines show `trend w`. | tested on CPU; the effect on pictures is item 59 |
| Resumable run | `--resume-every N` / Resume node (`directory`, `every`, `identity`) wired to the model, the optimizer (and the weight average), the Trainer's `start_step`, the Batcher's `skip`, and the trainer's step and end events | Every N steps the adapter, the optimizer's moments and counter, the weight average, the step and the data position are written to `<output>/resume` as `resume_<step>.safetensors` + `.json` (the json, with the size and SHA-256 of the tensors, is written last and marks the state complete; both files are flushed to disk and the newest two are kept). Running the same command again loads the newest state that is whole (a damaged one is skipped for the one before it), restores everything and continues: steps, learning-rate schedule, region ladder, batch ramp and data order go on exactly (a unit test shows the final adapter equals the uninterrupted run's). A state of a different run (another learning rate, rank, dataset, options other than how long it runs) is refused; delete the folder to start over. A run stopped on request leaves a state at its last step; a finished run keeps its states (the lab deletes them once the result is safe). Not restored: the time balance's statistics and the self-perceptual loss's random stream (a resumed run restarts them). The lab trains every arm with `--resume-every 200` (`"resume_every"` in the experiment file, 0 = off). | about 0.5 GB of disk per state (two kept) and a few seconds per save | untested on hardware (TESTING 58) |
