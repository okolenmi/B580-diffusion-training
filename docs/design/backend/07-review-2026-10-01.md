# Backend/frontend redesign: review findings (2026-10-01)

Reviewed at commit `52a9bc2` (M8a). Scope: `backend/` (about 12k lines),
`frontend/` (about 8k lines), and how they relate to the legacy `server/`.
Backend suite at that commit: 21 files, all passing. Legacy suites and the
Playwright visual smoke were **not** run.

**Evidence legend.** `[R]` = reproduced by running real project code in a
sandbox (CPU only, no XPU, no real SDXL, no browser). `[C]` = read from the
source, not executed; treat as a strong lead, confirm before relying on it.

**Severity.** High = data loss, a state that blocks the app until restart, or
unauthenticated write/exec. Medium = wrong behaviour in a plausible situation.
Low = latent or cosmetic.

## 2. Findings in detail

### F-01 Supervisor dies on a malformed progress line [R]
`_sample()` converts fields with `int(...)` and `float(...)` on whatever the
file contains. A line such as `{"phase":"step","step":"n/a"}` is valid JSON,
so it passes the `json.loads` guard and then raises inside the supervisor
thread. `_guard` logs and the thread ends. Nothing finalises the run: it stays
`running` after the trainer exits, and `StartTraining` returns 409 until the
backend restarts. (Stopping it by hand would mark a finished run `cancelled`.)
The graph supervisor already has the right pattern (`_fail_leftover`); the
training supervisor does not.
**Fix direction.** Guard each line (coerce or skip, never raise out of
`read_new`); give `RunSupervisor._guard` a crash-repair path equal to
`GraphExecutionSupervisor`.
**Regression tests.** (a) progress line with wrong types does not stop later
lines being applied; (b) supervisor crash finalises the run as `failed` and a
new start is then accepted.

### F-02 Stranded `created` row [R]
`StartTraining` inserts the row, then calls `artifacts.prepare()` and
`gateway.spawn()`. `spawn()` correctly wraps its errors; `prepare()` does not.
A `PermissionError` there leaves the row `created`, `find_active()` counts
`created` as active, and every retry reports the old run as still active.
**Fix direction.** Do everything that can fail before inserting, or wrap the
whole sequence so any exception marks the row `failed` before re-raising.
**Regression test.** `prepare()` raises, then a second start succeeds.

### F-03 NaN/inf losses [R + C]
`json.dumps` with default `allow_nan=True` emits bare `NaN`. A browser
`JSON.parse` throws on it. Both frontend handlers swallow the error
(`catch { return; }`), so the first diverged step simply disappears from the
dashboard. Divergence is exactly when this data matters.
**Fix direction.** Sanitize at the serialization boundary (e.g. `null` plus a
`nonfinite: "nan"|"inf"` field) and have the UI render it as a loud state.
Never swallow a parse error silently; count and surface it.
**Regression tests.** serializer output parses with a strict JSON parser for
NaN/inf; a frontend check that a non-finite frame is shown, not dropped.

### F-04 Run-id collision with legacy history [R]
The new database hands out run id 1 again, and `spawn()` opens
`runs/run_1/log.txt` with `"w"`. Demonstrated: a 5100-byte legacy log became 0
bytes. Doc 03's statement that log files "stay untouched either way" is false
for any colliding id. (The trainer's own `ProgressWriter` also truncates, so
stale progress is not replayed, but the logs are lost.)
**Fix direction.** Seed the new id sequence above the highest existing
`runs/run_*` directory, or refuse to start if the directory already has
content; correct the doc.
**Regression test.** existing `run_1/log.txt` is preserved when the first new
run starts.

### F-05 `discard()` ordering [R]
Shard files are unlinked inside the open transaction, before commit. With a
forced failure on the second file the DB rolled back (2 rows still present)
while the first shard file was already gone, so the dataset references a
missing shard.
**Fix direction.** Delete rows and commit first, then remove files, tolerating
(and reporting) leftovers; orphaned files are recoverable, dangling rows are
not.
**Regression test.** failure during file removal leaves every referenced shard
present.

### F-06 Unauthenticated API [R chain, no exploit built]
There is no auth and no Host/Origin validation (`app.py` installs no
middleware). Demonstrated with two requests: `POST /settings {loras_dir}`
(validation creates the directory) then `PUT /assets/lora/files/payload.sh`
wrote an arbitrary file outside any managed directory. `venv_python` only has
to be an existing file and is later executed. Uploads read the whole body into
RAM and write straight to the final path (multi-GB checkpoints; partial file
visible on failure). The asset-store docstring says the API is meant to be
reachable from another machine.
**Fix direction.** Host-header allowlist (stops DNS rebinding), an
Origin/token check on state-changing requests, extension allowlists per asset
kind, streamed uploads to a temp file then atomic rename, require
`venv_python` to be an executable inside an allowed location or report it as
advisory only.
**Regression tests.** foreign Host header rejected; disallowed extension
rejected; failed upload leaves no file at the final path.

### F-07 Lost progress samples [R]
Two separate gaps. (1) The supervisor checks `is_alive` before reading, so
lines written just before exit are never read; my repro used the worst case
(everything written and the process gone inside one tick) and showed a
completed run at 0/100. In real runs the loss is the last few samples. (2) The
reader iterates a text file and stores `tell()` after the loop, so a
half-written last line is skipped and the offset moves past it; when the rest
arrives that sample is unrecoverable (repro: step 42 lost). Neither has a
test.
**Fix direction.** Consume only newline-terminated lines and keep the
remainder buffered; do one final `read_new` after the process is seen dead;
set `done_steps` from the final sample on completion.

### F-08 "Raw" TOML is not raw [R]
The raw endpoint parses into the pydantic model and rewrites the file.
Comments, ordering and unknown keys are dropped, and the response is 200.
For a project where users tune hyperparameters and keep notes in the file,
this is silent data loss.
**Fix direction.** Validate the text, then write the user's original text
(atomic temp + replace); keep model-based rewriting only for the form editor.

### F-09 Event stream resync [C]
`dashboard.js:466` subscribes with `onMessage` only. `/events` has no replay,
and the server drops the newest event when a client queue is full, so a
missed `run_completed`/`run_failed` leaves the hero stuck on "running" until
reload. Startup reconcile publishes before any client is subscribed, which
has the same effect. The editor's execution stream also has no resync.
**Fix direction.** Refetch authoritative state on every (re)open, coalesce
progress events and never drop lifecycle events, add a slow safety poll.

### F-10 Dataset create deletes foreign directories [C]
If `datasets/<name>` exists without a `metadata.db`, `create()` runs
`shutil.rmtree` on it ("ghost directory" legacy rule). A user's raw image
folder with the same name is silently destroyed.
**Fix direction.** Only remove a directory that contains nothing but the empty
skeleton this code creates; otherwise raise a conflict error.

### F-11 Restart kills live training [C, inherited]
Trainers are started in their own session so they survive a server restart,
then startup reconcile SIGKILLs them. The legacy server did the same, so this
is a decision to confirm. Everything needed to re-adopt the process (pid,
progress file, offset) already exists.

### F-12 Process gateway safety [C]
`stop()` signals without the cmdline guard that `kill()` uses; escalation to
SIGKILL happens after 3 s, which may be too short for a trainer saving
optimizer state; `is_alive` treats `PermissionError` as dead. The dataset
gateway implements the same ideas with a stricter marker check; the two should
share one implementation.

### F-13 In-process graph training [C]
Node-graph training (the resource-controller line) executes inside the API
server process. A device fault, OOM kill or restart takes the server and the
run with it, and the event loop competes with the training thread. The docs
accept this; the risk and the "restart = lose the run" consequence should be
stated next to it, and subprocess isolation (as for `core.cli`) recorded as a
follow-up.

### F-14 Unbounded work [C]
`GetRunLog` reads the entire log to return 500 lines (and does file I/O in the
application layer although a port exists). Dataset item listing has no
limit/offset (the runs list does). Uploads are whole-body. The monitor stream
queue has no bound and history replay blocks the event loop. `_describe`
calls `repr()` on arbitrary objects before truncating.

### F-15, F-16 Smaller ones [R]
Rejected settings updates still create directories (violates the store's own
"nothing written" claim). `executescript` migrations are not atomic; a
failure midway leaves a half-applied schema that fails again on every start.
Fine today, a trap for the next `ALTER` migration.

## 3. What is good (do not "fix")
- Layering holds: an AST audit found no inward/outward import violations; the
  domain imports no third-party code.
- Zero `innerHTML` sinks in the frontend; everything uses `textContent`.
- Path sandboxing for relative asset paths is sound, including symlinks.
- Compare-and-set per state transition is applied consistently.
- `spawn()` wraps every launch failure in `TrainingLaunchError`.
- Config writes are atomic (temp + replace).
- The tests' `try: ...; check(False) / except X: check(True)` idiom is correct
  (the failing branch is inside the `try`), so those tests are not vacuous.
- The real composition root is exercised by five API tests.

## 4. Where quality needs to improve (instructions for a coding AI)

Apply these to every change in `backend/` and `frontend/`. Each rule comes
from a finding above.

1. **Every background thread needs a crash-repair path.** If it can die, the
   row it owns must still reach a terminal state. Copy the graph supervisor's
   pattern; add a test that kills the worker mid-run. (F-01)
2. **Everything from outside the process is hostile input**: files the
   trainer writes, request bodies, settings values, uploaded names. Parse per
   record, coerce types, tolerate partial and non-finite values, never let one
   bad record end a loop. (F-01, F-03, F-07)
3. **Validate first, then act.** No row, directory or file may be created
   before every check has passed; if an action sequence can fail midway, make
   the failure path leave a consistent state. Commit DB changes before
   deleting files. (F-02, F-05, F-15)
4. **Never emit non-JSON.** Sanitize at the serialization boundary and test
   with a strict parser. (F-03)
5. **No silent swallowing.** `catch { return; }`, `except Exception: return
   default` and similar must count or surface what they drop. A swallowed
   error in a monitoring tool hides exactly the failures it exists to show.
   (F-03, settings `get()`)
6. **Frontends resync on every (re)connect** and treat an event stream as
   lossy. (F-09)
7. **Secure by default.** Allowlist Host, check Origin/token on writes, limit
   extensions and sizes, stream and atomically rename uploads, never let one
   endpoint choose what another executes. (F-06)
8. **Test failure paths, not only happy paths.** For every start/write flow
   add a test where a dependency raises; for every parser add torn,
   malformed, truncated, NaN and empty cases; use the reproductions
   (appendix) as the starting point.
9. **Treat "legacy parity" as a warning label, not a justification.** Several
   defects above are faithful ports. Confirm the behaviour is wanted.
10. **Docs must be true.** Do not write a guarantee (such as "logs stay
    untouched") without a test that proves it; update README,
    `docs/architecture.md`, `docs/setup.md` and `docs/status/progress.md`,
    none of which mention `backend/` or `frontend/` yet.
11. **One implementation per concern.** The two process gateways, the
    near-copy `config_schema.py`/`config_ui_data.py` (about 92% identical to
    legacy) and the `build_services` twin of `bootstrap.py` will drift. Fix
    in the new copy only, share code, or delete the legacy copy at M9.
12. **Keep units small.** `schemas.py` is 900 lines (split by API module),
    `GraphRuntime.validate` is 171 lines (split per pass), `monitor.js` and
    `loss_chart.js` are about 680 lines each.
13. **Put the frontend under test.** The gate only runs `node --check`; add
    tests (even a small DOM harness) for event handling, reconnect resync and
    non-finite values, and put the Playwright smoke in the gate or document
    why not. Remove the hardcoded home path from `scripts/full_gate.sh`.

## Appendix: reproductions
Eight small scripts in `scripts/repro/` reproduce F-01/F-02/F-07
(supervisor + start flow), F-06/F-15 (write chain), F-08 (raw TOML),
F-07/F-03 (torn line, NaN), F-04 (run-id collision), F-16 (migration) and
F-05 (discard). Run them from the repo root with the backend's python:
`python scripts/repro/rN_*.py` (see `scripts/repro/README.txt` for the
finding-to-script map). They use the project's own
`backend/tests/support.py` helpers, only touch temp directories, and are
written to be converted into regression tests in the repo's `check()`
style. Re-run 2026-10-01 at `c1dc136`: all eight still reproduce
(section 7).
